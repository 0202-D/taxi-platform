# Monitoring Platform

Monitoring Platform — распределённая система мониторинга доступности веб-сайтов и интернет-сервисов.

## Идея проекта

Система позволяет пользователю добавлять сайты и сервисы, которые необходимо контролировать.

Для каждого ресурса система периодически выполняет проверки и сохраняет результаты. Пользователь может видеть состояние своих ресурсов и получать информацию о возникших проблемах.

Планируется контролировать:

- доступность сайта;
- HTTP status code;
- время ответа;
- SSL-сертификат и срок его действия;
- DNS и доступность домена;
- срок регистрации домена;
- историю проверок;
- возникновение и завершение инцидентов.

В дальнейшем система сможет отправлять уведомления о проблемах.

## Общая архитектура

Проект состоит из нескольких независимых сервисов.

### monitor-web

Веб-интерфейс приложения на Vaadin.

Отвечает за:

- интерфейс пользователя;
- регистрацию и вход;
- работу с авторизованной сессией;
- отображение состояния и результатов мониторинга.

### user-service

Сервис, отвечающий за пользователя на уровне самого приложения.

Аутентификация и хранение учётных данных выполняются в Keycloak. `user-service` хранит данные пользователя, необходимые непосредственно Monitoring Platform, и связывает их с идентификатором пользователя в Keycloak.

### monitoring-service

Основной бизнес-сервис системы мониторинга.

Отвечает за:

- создание и изменение мониторов;
- настройки проверок;
- запуск и планирование проверок;
- обработку результатов;
- управление инцидентами.

### monitor-worker

Отдельный компонент для выполнения фактических проверок ресурсов.

В перспективе он будет выполнять:

- HTTP-запросы;
- проверки SSL;
- DNS-проверки;
- другие внешние сетевые операции.

Для передачи заданий между сервисами планируется использовать Apache Kafka.

## Аутентификация

Для аутентификации и управления учётными записями используется Keycloak.

Приложение не хранит пароли пользователей самостоятельно.

Общий сценарий:

Browser → monitor-web → Keycloak → JWT → backend services

Keycloak отвечает за identity и authentication, а прикладные сервисы используют информацию из JWT для определения текущего пользователя.

## Основная идея разделения ответственности

Проект намеренно разделён на отдельные бизнес-области:

Keycloak
→ identity и authentication

user-service
→ данные пользователя приложения

monitoring-service
→ логика мониторинга

monitor-worker
→ выполнение внешних проверок

Это позволяет развивать отдельные части системы независимо и постепенно масштабировать наиболее нагруженные компоненты.

## Цель проекта

Проект создаётся как production-like pet project для практического применения современных подходов к разработке распределённых Java-приложений.

Основные технологии и направления:

- Java;
- Spring Boot;
- Spring Security;
- OAuth2 / OpenID Connect;
- Keycloak;
- Vaadin;
- PostgreSQL;
- Liquibase;
- Apache Kafka;
- Docker;
- Docker Compose;
- Kubernetes;
- Kong;
- Testcontainers.

Проект развивается постепенно: от работающего MVP к распределённой системе с асинхронной обработкой, масштабированием, мониторингом и уведомлениями.
